# Brainstorming Ideas

## Cuándo usar esta habilidad
- Antes de escribir código para una nueva funcionalidad.
- Cuando el usuario tiene una idea vaga o incompleta.
- Para explorar alternativas de diseño.

## Flujo de Trabajo
1.  **Entender el Contexto**: Revisar el estado actual del proyecto.
2.  **Refinar la Idea (Socrático)**: Hacer preguntas *una a una* para clarificar requisitos.
3.  **Explorar Enfoques**: Proponer 2-3 alternativas con sus pros y contras.
4.  **Validar Diseño**: Presentar el diseño final en secciones pequeñas para aprobación.

## Instrucciones

### 1. Entendiendo la Idea
- No asumas. Pregunta.
- Prefiere preguntas de opción múltiple para facilitar la respuesta.
- Identifica: Propósito, Restricciones, Criterios de Éxito.

### 2. Explorando Enfoques
- Siempre ofrece alternativas. (ej. "¿Usamos una librería existente o construimos algo custom?")
- Recomienda una opción y justifica por qué.

### 3. Documentación
- Una vez acordado, documenta el diseño.
- Si es complejo, sugiere crear un artefacto de diseño (`design_doc.md`).

## Principios
- **Una pregunta a la vez**: No abrumes al usuario.
- **Validación Incremental**: Avanza paso a paso.
- **Flexibilidad**: Si algo no tiene sentido, retrocede y clarifica.
